## Definition

This file describes a persuasive application / argument flow based on quy nap logic. It helps the agent guide reader awareness and trust before presenting an offer, conclusion, or CTA.

It is not confirmed as a fully independent original layout in Batch 2B.

## Core Principle

Use quy nap or another validated root layout as the structural base, then apply persuasive sequencing: build context, trust, and acceptance before asking for action.

This file supports persuasion; it does not replace `quy-nap-layout.md`.

## Goal

- Build trust before conversion.
- Reduce reader resistance by showing reasons, stories, or evidence before the ask.
- Make the final offer or CTA feel like a natural next step.

## When To Use

- When the content goal is persuasion or conversion.
- When the audience is not ready to buy immediately.
- When there is enough story, proof, or reasoning to support a delayed offer.
- When used with quy nap or another validated root layout.

## When Not To Use

- Do not use as an independent layout without validating against taxonomy.
- Do not use when the task needs a quick announcement or short direct-response message.
- Do not use when there is no evidence, story, or reasoning to support the persuasion path.
- Do not use as a CTA bank or hook framework.

## Structure

Step 1: Select a validated root layout, usually quy nap when the final conclusion is delayed.

Step 2: Open with a situation, question, or story without forcing the offer.

Step 3: Build trust through evidence, experience, or logical steps.

Step 4: Summarize the conclusion.

Step 5: Present the offer or CTA as the natural next action.

## Content Flow

Root layout -> persuasive context -> trust-building reasoning -> conclusion -> action.

## Mini Example

Topic: website service.

- Root layout: quy nap.
- Situation: ads bring leads, but customers keep asking for basic information.
- Evidence: social posts disappear, inbox replies repeat, pricing is hard to find.
- Conclusion: a website reduces friction in the buying journey.
- CTA: request a website structure review.

## Common Mistakes

- Using this file instead of choosing a root layout.
- Treating persuasion as a CTA-only problem.
- Adding an offer before trust is built.
- Listing evidence without connecting it to a conclusion.
- Calling it a hook framework.

## Checklist

- [ ] Has a root layout been selected first?
- [ ] Was `quy-nap-layout.md` checked if the conclusion is delayed?
- [ ] Is the persuasive sequence tied to the content goal?
- [ ] Does the offer or CTA follow the reasoning naturally?
- [ ] Is this file used as application logic, not as a standalone layout?

## Difference From Similar Layouts

- Different from quy nap: quy nap is the structural pattern; this file adds persuasive intent and conversion awareness.
- Not a replacement for quy nap: validate with `quy-nap-layout.md` before using it.
- Not CTA: CTA is the final action; this file describes how to build acceptance before that action.
- Not hook: hook attracts attention at the start; this file manages the persuasion path across the content.
- Different from moc xich: moc xich focuses on idea-to-idea continuity; this file focuses on trust-to-action progression.
