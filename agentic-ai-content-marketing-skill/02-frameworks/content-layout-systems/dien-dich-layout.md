## Definition

Working definition based on available comparison sources: dien dich is described as a layout where the main point appears at the beginning, then the following content explains or supports that point.

This is not a fully validated standalone layout file yet because Batch 2B only found comparison/overview references, not a dedicated dien dich source.

## Core Principle

Use the main point first, then explain, prove, or expand it. Treat this principle as medium-confidence until a direct source is ingested.

## Goal

- State the key message quickly.
- Support short announcements or direct-response content.
- Help readers understand the main idea without waiting for a delayed conclusion.

## When To Use

- Use only when `layout-selection-matrix.md` and `layout-taxonomy.md` mark it suitable.
- Use only when source confidence is acceptable for the task risk.
- Use when the content goal needs the conclusion or claim at the beginning.
- Use for low-risk drafts, short notices, or comparison tasks where directness matters.

## When Not To Use

- Do not use if the task requires a layout with direct High-confidence source support.
- Do not use as the main layout in important content until this file is reviewed with a dedicated source.
- Do not use when the content needs storytelling, curiosity, or gradual trust-building.
- Do not use when the audience may resist a conclusion stated too early.

## Structure

Step 1: State the main point.

Step 2: Explain the reason.

Step 3: Add supporting details or evidence.

Step 4: Close with the message or action.

## Content Flow

Main point -> reason -> support -> close.

## Mini Example

Topic: AI automation.

- Main point: Small businesses should standardize repeated tasks before buying more AI tools.
- Reason: tools cannot fix an unclear process.
- Support: if lead handling is messy, automation only repeats the mess faster.
- Close: map the process first, then choose the tool.

## Common Mistakes

- Treating this as High-confidence when only comparison sources are available.
- Stating a strong claim first without enough support.
- Using it for content that needs curiosity or narrative tension.
- Skipping taxonomy validation.

## Difference From Similar Layouts

- Compared with quy nap: dien dich starts with the main point; quy nap delays the main point until the end.
- Compared with tong phan hop: tong phan hop states the main point early and returns to it at the end; this file only has comparison-based support for a simpler main-point-first pattern.
- Compared with moc xich: moc xich focuses on how one idea bridges to the next, not only where the main point appears.
